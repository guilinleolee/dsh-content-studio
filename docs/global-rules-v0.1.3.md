## 第一部分：统一存储规范

### 1.1 目录体系总览

DSH 根目录：`~/.dsh/`（开发提示词中统一使用相对/抽象描述，禁止出现本机绝对路径）

```
~/.dsh/
├── outputs/                         # 作品库（唯一业务数据面）
│   ├── _schedule.json               # 全局排期/定时任务（下划线系统文件，不作为作品）
│   ├── _calendar.json               # 日历日期备注（_schedule 的旁注，不进 _schedule 本体）
│   ├── _topics.json                 # 选题库清单
│   ├── _personas.json               # 账号画像清单（内嵌全文，自包含备份）
│   ├── _gather.json / _competitors.json / _create.json / _create-quota.json
│   ├── _templates.json / _publish.json / _publish-index.json / _publish-profiles.json
│   ├── _review-index.json / _interactions.json
│   ├── <主题>/
│   │   ├── .dsh-output.json         # 该主题唯一业务元数据文件
│   │   ├── <成品文件>               # 成品：定稿稿件、最终报告
│   │   └── assets/                  # 中间素材：草稿、抓取原文、摘要、截图、平台适配稿、
│   │                                #   复盘报告与模板（assets/review/）、各栏目清单旁注（_review.json、_gather 素材清单等）
└── templates/                       # 全局模板资产（懒创建，不属于任何主题）
    ├── templates.json               # 模板记录
    ├── taxonomy.json                # 共享标签分类
    └── history/<template-id>/<version>.json   # 手动保存的版本快照
```

规则：`_` 前缀与 `.` 前缀文件为系统文件，作品库扫描一律跳过（`scan.ts` 对主题目录、assets 内文件、根文件三处一致生效）；系统文件只增不删是硬约束——新增系统文件必须先入本图再落码。

### 1.2 各类数据落位规则（强约束表）

| 数据类型 | 落位 | 说明 |
|---|---|---|
| 成品文件 | outputs/`<主题>`/ 根目录 | 定稿稿件、成品内容、最终版本 |
| 中间素材 | outputs/`<主题>`/assets/ | 草稿、抓取原文、HTML、截图、摘要、AI 生成片段、数据快照、复盘报告（assets/review/）、平台适配稿 |
| 主题业务元数据 | `<主题>/.dsh-output.json` | 该主题唯一业务元数据；各栏目业务实例、版本列表、关联 ID、状态 |
| 栏目清单类业务资产 | 库根 `_*.json`（见 1.1 图） | 画像、对标账号、选题、发布任务与账号矩阵、采集配置旁注等（D1 决策） |
| 全局排期/定时 | outputs/_schedule.json | 选题排期、发布定时任务、日历事件；下划线文件不展示在作品库 |
| 模板资产 | ~/.dsh/templates/ | 模板正文、变量定义、版本快照；跨主题/跨栏目复用；懒创建 |
| UI 草稿/选中项/筛选视图配置/账号选择 | 浏览器 localStorage | 仅可丢失可重建数据（1.5）；四步向导草稿、当前选中画像/账号/主题、日历筛选等 |
| 账号密码、token、敏感凭据 | 禁止存储（任何位置） | 账号矩阵仅存别名、启用状态、适配参数 |

### 1.3 关键边界规则（强制）

- 磁盘写入触发条件：只有智能体产出内容、或用户明确保存时，才写入 output 目录；纯前端交互（点击按钮、复制指令、切换视图）不产生任何磁盘文件。
- 禁止新增 `~/.dsh` 根目录自定义文件夹；系统文件只进库根文件位。
- 素材与成品严格分区：中间素材一律进 assets/，只有定稿/成品放主题根目录。
- 引用优先，不重复拷贝：跨栏目关联（素材→选题、画像→创作、稿件→发布）一律用 ID/文件名引用溯源，不复制原始文件；引用可携带 title/summary 元数据快照，不得内嵌正文。例外：`_personas.json` 画像条目内嵌自身全文——画像清单是自包含备份单元，不构成跨栏目拷贝（D1 决策的一部分）。
- 元数据唯一：每个主题只有一个 `.dsh-output.json`。

### 1.4 元数据 .dsh-output.json 通用约定

文件必须合法 JSON、UTF-8 无 BOM；写入走「先校验后原子落盘」（assert 校验 + 文件锁 + 临时文件原子替换）；顶层结构按主题组织，各栏目业务实例以「栏目类型 + 实例ID」为键；关联字段用引用 ID（source_id、topic_id、persona_id、template_id、calendar_event_id、manuscriptFile 等）；每次业务实例创建/更新/删除同步更新该文件，排期变化额外同步 `_schedule.json`；文件读写统一走 content-outputs 网关，不直接操作文件系统。

### 1.5 localStorage 约定（v0.1.3 修订）

仅存放：四步向导草稿与表单中间态、当前选中项（画像/账号/主题/标签页）、各栏目筛选与视图配置、功能开关记忆。键名统一 `dsh-content-studio.` 前缀（D7）；历史键迁移带读旧回退，旧键在首次保存时清除。均为可丢失可重建数据；不得存放业务实例清单（D1：已上盘）、账号密码、token。已知键族：`dsh-content-studio.gather.*`（源与任务配置）、`dsh-content-studio.competitors.*`（对标账号在 D1 前的历史遗留位，读侧兼容）、`dsh-content-studio.calendar.config`、persona 向导草稿与选中项键。

### 1.6 已知限制（如实声明，非豁免）

- 跨文件非原子窗口：选题保存/删除级联（`_schedule.json` ↔ `_topics.json`）与日历拖拽联动选题计划日期，均为「先 A 后 B」两段写，第二步失败仅提示不回滚，可能留下悬挂引用或日期分叉。当前相接受（失败文案显式），二期存储迁移时统一事务化。
- 原子写不含 fsync：`dsh-atomic-write` 保证进程内原子替换，崩溃时可能丢最后一次写。
- 违禁词预检为简化实现：内置约 90 词、朴素匹配、列表展示；命中高亮、修改建议、分类词库热更新为后续增强项（2.3 的「仅提示不拦截 + 免责」约束不变）。

## 第二部分：组件规范

### 2.1 全站视觉与交互统一

统一风格与组件复用清单沿用 v0.1.2-rc.5：列表（表格）、卡片、侧边详情面板、弹窗/浮层、标签筛选、Markdown 编辑、分页/搜索/筛选控件全站复用，禁止各栏目重造；同一语义（新建/保存/编辑/删除）全站同一按钮文案。

- 日历组件：自研过渡实现（月/周/列表三视图，拖拽确认后落库），触发条件见 D3；在触发条件命中前不引入 FullCalendar。
- 图表组件：当前以汇总卡/排行榜/文本可视化实现，不引图表库；首个真实图表需求出现时统一评估 Chart.js，全站只用一个图表组件。

### 2.2 状态语义统一

- 选题状态（钦定词表，实现已逐字对齐）：灵感待评估 / 待创作 / 创作中 / 已完成 / 暂存搁置（`idea / todo / creating / done / shelved`）。
- 任务状态：待执行 / 采集中 / 完成 / 失败。
- 发布状态（本期过渡态，D2）：草稿 / 待复核 / 待定时 / 已记录；平台腿：未适配 / 已适配 / 已手改 / 已记录。二期终态模型（执行中、部分成功、全部成功、全部失败、失败隔离）随 MCP 通道设计，词汇届时以用户语言复核。
- 同一状态全站同色；空态、加载态、错误提示全站统一处理。

### 2.3 布局与交互规范

布局沿用 v0.1.2-rc.5（顶部筛选+主内容区；左列表右详情；分步向导带步骤指示条）。交互强制：

- 破坏性操作（删除、清空缓存、覆盖）必须二次确认——七处已对齐（D6），新增破坏性入口必须同规则。
- 拖拽类操作（日历编排、看板改状态）修改后确认再落库；写入失败自动回滚并提示。
- AI 生成结果一律先以草稿形式呈现，人工确认/编辑后才可保存或流转；AI 显式触发，不进保存主路径。
- AI 输出界面必须附「建议人工核对」类提示（画像补全、创作评估、模板 AI、发布适配四处已对齐；新增 AI 面同规则）。
- 违禁词预检仅提示不拦截保存/导出，页面附免责声明。

## 第三部分：MCP 预留规范

### 3.1 本期预留现状（D4 收窄）

本期统一只做「预留调用入口 + UI + 数据结构」，不实现底层爬虫/自动化/上传。已落地接缝：发布冻结交接包——「执行发布」生成全部平台腿的 complete-or-not 交接包并翻 `recorded`，真实上传由二期 MCP 通道消费；采集/对标侧接口以注释与「待接入」降级提示预留。

### 3.2 能力意图表（命名与归属保留，Schema 不在本期交付）

| 能力域 | 涉及栏目 | 意图命名 | 本期行为 |
|---|---|---|---|
| 网页/账号内容抓取 | 信息、对标、画像 | fetch_source | 手动粘贴/手动导入，入口预留 |
| RSS 拉取 | 信息 | fetch_rss | 采集调度在工作台打开期间本地执行，底层抓取本地化实现 |
| 平台数据拉取 | 复盘 | fetch_platform_stats | 仅手动导入 CSV |
| 评论/私信消息拉取 | 互动 | fetch_messages | 仅手动导入 CSV |
| 真实发布/上传 | 发布 | publish_content | 仅生成交接包记录状态 |
| 回复发送 | 互动 | send_reply | 仅本地草稿存档 |
| 官网内容解析 | 画像 | resolve_website | 仅录入 URL，解析预留 |

### 3.3 统一封装层（二期立项）

统一 MCP 调用封装层 + 七能力入参/出参契约，立项条件 = 第二个真实消费者出现（D4）。未接入能力的按钮必须给明确「待接入」提示，不得静默失败；单平台/单源失败隔离（采集侧已实现逐源隔离与指数退避，发布侧 per-leg 状态机已为隔离留缝）。

### 3.4 安全约束（沿用原文）

禁止在插件内存储或请求用户平台账号密码/token；浏览器自动化、真实发布、消息发送等高风险能力必须人工确认后执行；所有 MCP 拉取数据本地落盘于 assets/，不上传第三方云端。

## 第四部分：全局约束

### 4.1 架构与集成约束

插件为 DSH 标准扩展：前端动态 JS 加载，经 `sidebar.footer.action` + `shell.overlay` 扩展槽位挂载，不侵入 DSH 主构建；后端为 content-outputs（含全部栏目文件面）、content-schedule（排期/日历）、content-topics（选题库）三个能力网关，自挂载自卸载，官方 BFF 零感知；文件读写统一复用上述网关；AI 能力统一走 DSH 内置 `llm` Service Definition（共享队列、限流重试策略），不新增独立大模型接口。

### 4.2 功能边界约束（本期范围）

本期为单人工作台版本，不做团队权限与多用户协作；媒体文件生成预留扩展接口；违禁词预检仅提示（1.6）；AI 补全基于模型知识推断，界面附「建议人工核对」提示，本期不做实时联网搜索；网页抓取、平台 API、真实发布、消息发送的底层能力不实现，预留形态见第三部分。互动栏目归属按 D5 由产品所有者签署。

### 4.3 安全与合规约束（沿用原文）

不存储、不请求用户账号密码/token；高风险动作必须人工审核确认，禁止全自动执行；业务数据本地优先保存在 output 目录，不上传第三方云端；外部输入（模板渲染、MCP 返回、抓取正文）渲染前必须消毒（DOMPurify/allowlist），不直接拼入可执行上下文；表单、URL、变量填写做合法性校验。

### 4.4 开发禁止清单

❌ 不修改 DSH 主仓库原有目录结构、output 文件规范、构建流程。❌ 不在 `~/.dsh` 根目录新建自定义文件夹（系统文件只进 1.1 图列出的文件位）。❌ 不把业务实例清单写入 localStorage（D1）。❌ 不把中间素材直接写到主题根目录。❌ 不改动 `_schedule.json` 原有读写逻辑。❌ 不新增独立文件网关、独立大模型接口。❌ 不硬编码爬虫/浏览器自动化/上传/发送底层逻辑。❌ 不侵入 DSH 主 Vite 构建。❌ 新增破坏性操作不带二次确认。❌ 新增 AI 输出面不带人工核对提示。

### 4.5 通用验证与交付要求

各栏目实现后按统一存储规范落盘，数据可被作品库正常加载；跨栏目联动（加入选题库、一键创作、排期同步、复盘回流、画像注入、模板调用）必须完整打通并验证；交付前检查：输入已读全、约束未越界、事实可追溯、关键动作已执行、产物已验证。审计与快照类任务必须先钉基线（commit SHA + 关键文件 mtime），结论只在基线上成立。
